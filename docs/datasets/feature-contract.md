# Federated Cyber Shield — Feature Contract Specification

**Architecture Baseline:** FCS v1.2  
**Component:** FCS-UDIP Feature Contract & Parity Matrix  
**Specification Version:** 1.2.0  

---

## 1. Overview

Federated Cyber Shield enforces a strict dual-specification architecture to bridge academic network benchmark datasets and real-world deployment telemetry:

1. **Research FeatureSpec:** The full 43-feature canonical NetFlow v2 benchmark specification extracted via nProbe, used for theoretical modeling, benchmark replication, and cross-dataset evaluation.
2. **Deployable FeatureSpec:** The subset of features that are directly generated by or strictly derivable from the Phase 1 `FlowEvent v1` streaming telemetry collector without requiring packet payload deep inspection (DPI) or proprietary router extensions.

---

## 2. Canonical 43-Feature Research Specification

The 43 canonical NetFlow v2 features established by Sarhan et al. (IEEE / arXiv:2101.11315) are classified into functional categories:

### 2.1 Flow Identifiers & Addressing (Privacy Sensitive)
| Feature Name | Type | Valid Range | Nullable | Description & Privacy Policy |
| :--- | :--- | :--- | :--- | :--- |
| `IPV4_SRC_ADDR` | String | Valid IPv4 | No | Source IPv4 address. **Masked to /24 prefix (`SRC_PREFIX_MASKED`) in training to avoid memorization.** |
| `IPV4_DST_ADDR` | String | Valid IPv4 | No | Destination IPv4 address. **Masked to /24 prefix (`DST_PREFIX_MASKED`) in training to avoid memorization.** |
| `L4_SRC_PORT` | Int64 | 0 – 65535 | No | Layer 4 transport source port. |
| `L4_DST_PORT` | Int64 | 0 – 65535 | No | Layer 4 transport destination port (service indicator). |
| `PROTOCOL` | Int64 | 0 – 255 | No | IP protocol number (e.g., 6 = TCP, 17 = UDP, 1 = ICMP). |

## 3. Feature Parity Matrix with Phase 1 FlowEvent v1

The table below demonstrates the exact correspondence between the benchmark dataset features and the Phase 1 streaming telemetry contracts:

| Canonical NetFlow Feature | Phase 1 FlowEvent Field | Parity Status | Resolution Strategy |
| :--- | :--- | :--- | :--- |
| `IPV4_SRC_ADDR` | `subscriber_prefix_masked` | `DERIVABLE_WITH_VERIFIED_TRANSFORM` | Dotted-quad masked to `/24` prefix matching tenant egress. |
| `IPV4_DST_ADDR` | `destination_ip` | `DIRECTLY_AVAILABLE` | Directly ingested and normalized. |
| `L4_SRC_PORT` | `source_port` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint16). |
| `L4_DST_PORT` | `destination_port` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint16). |
| `PROTOCOL` | `protocol` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint8). |
| `IN_BYTES` | `bytes_forward` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint64). |
| `OUT_BYTES` | `bytes_reverse` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint64). |
| `IN_PKTS` | `packets_forward` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint64). |
| `OUT_PKTS` | `packets_reverse` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (uint64). |
| `FLOW_DURATION_MILLISECONDS` | `duration_milliseconds` | `DIRECTLY_AVAILABLE` | Direct 1:1 mapping (float64). |
| `TCP_FLAGS` | `tcp_flags` | `DIRECTLY_AVAILABLE` | Direct 1:1 bitwise OR mapping (uint8). |
| `FLOW_START_MILLISECONDS` | `flow_start_epoch_ms` | `DIRECTLY_AVAILABLE` | Epoch millisecond integer. |
| `FLOW_END_MILLISECONDS` | `flow_end_epoch_ms` | `DIRECTLY_AVAILABLE` | Epoch millisecond integer. |
| `SRC_TO_DST_SECOND_BYTES` | `throughput_forward_bps` | `DERIVABLE_WITH_VERIFIED_TRANSFORM` | Derived via `(bytes_forward * 8) / (duration_s)`. |
| `DST_TO_SRC_SECOND_BYTES` | `throughput_reverse_bps` | `DERIVABLE_WITH_VERIFIED_TRANSFORM` | Derived via `(bytes_reverse * 8) / (duration_s)`. |
| Packet Histogram Fields (5) | N/A | `REQUIRES_ADDITIONAL_EXPORT_FIELDS` | Excluded from Deployable FeatureSpec; retained in Research FeatureSpec. |
| TCP Window Fields (6) | N/A | `REQUIRES_ADDITIONAL_EXPORT_FIELDS` | Excluded from Deployable FeatureSpec; retained in Research FeatureSpec. |
| DPI / Application Attributes | N/A | `UNAVAILABLE` | Excluded from Deployable FeatureSpec. |

## 4. Deployable Feature Subset Rules

When generating model-ready datasets for production deployment:
1. `FeatureHarmonizer.get_deployable_feature_matrix()` extracts only the 14 confirmed deployable fields.
2. Any feature marked `REQUIRES_ADDITIONAL_EXPORT_FIELDS` or `UNAVAILABLE` is strictly rejected from entering deployable training arrays.
3. Live inference models in Phase 3 trained on the Deployable FeatureSpec will execute with zero missing-feature imputation penalties.
