## 3. How to Consume the Model in Phase 4

Phase 4 should instantiate the reusable `InferenceEngine` from `fcs_ml.inference.engine`:

```python
from fcs_ml.inference.engine import InferenceEngine

# 1. Initialize engine (loads candidate registry from disk)
engine = InferenceEngine(registry_dir="artifacts/candidate-models")

# 2. Score incoming FlowEvent telemetry
flow_record = {
    "L4_SRC_PORT": 443,
    "L4_DST_PORT": 52140,
    "PROTOCOL": 6,
    "L7_PROTO": 91,
    "IN_BYTES": 1500,
    "OUT_BYTES": 4500,
    "IN_PKTS": 10,
    "OUT_PKTS": 25,
    "FLOW_DURATION_MILLISECONDS": 450.0,
    "TCP_FLAGS": 27,
    "CLIENT_TCP_FLAGS": 27,
    "SERVER_TCP_FLAGS": 18,
    "DURATION_IN": 200.0,
    "DURATION_OUT": 250.0,
}

result = engine.score_record(
    record=flow_record,
    model_id="lightgbm_deployable_subset",
    tenant_context="rural-isp-alpha",
)

# 3. Present structured result to Analyst Dashboard
print(f"Prediction: {result.predicted_label}")            # "Attack" or "Benign"
print(f"Confidence: {result.calibrated_probability:.4f}")  # Calibrated probability
print(f"Status:     {result.status}")                      # "SCORED" or "ABSTAIN"
print(f"Latency:    {result.latency_microseconds:.2f} µs") # Flow scoring latency
```

## 4. Manual Mode Governance and Safety Constraints

Phase 4 implements **Manual Mode MVP** only. The following architectural constraints are strictly enforced:
1. **Zero Automated Network Actions:** The ML inference engine returns `network_action_executed = False` on every flow. Under no circumstances may Phase 4 components execute firewall rules, BGP null-routes, or router reconfigurations based on raw model scores.
2. **Analyst Presentation Only:** Scores and alert indicators must be queued for human analyst review in the tenant-isolated dashboard.
3. **Artifact Integrity Verification:** Always verify model checksums via `CandidateModelRegistry.verify_model_artifact("lightgbm_deployable_subset")` before loading in production services.
